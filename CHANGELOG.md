# Changelog

All notable changes are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning: [SemVer](https://semver.org/).

## [Unreleased]

First version: reads BatInspector's export file and publishes one observation per entry to iNaturalist, with the spectrogram and the recording as evidence.

### Added

- Targets net8.0 and net10.0.
- Input file (schema v1, `InputSchemaReader`, required `SchemaVersion`), see `docs/input-format.md`:
  - Validation per entry: a bad entry is left out of `InputDocument.Candidates` and reported in `InputDocument.Rejected` with the path of the field; only a structurally unusable file throws. Evidence paths must be absolute and end in `.png` / `.wav`; the position 0, 0, coordinates out of range and dates in the future (compared as instants) are rejected.
  - `InputDocument.Warnings` for accepted but doubtful entries: the ambiguous repeated autumn hour, a `Temperature` outside -40 to 60 °C or a `Humidity` outside 0 to 100 % (left out of the candidate), a time between 09:00 and 15:59 (daylight), a `SpeciesLatin` of three or more words, and an entry repeating an earlier one (same species, time and position).
  - Times are read as Europe/Berlin local time with the right offset, or in the zone of the optional `TimeZone` field (IANA id, `ObservationCandidate.TimeZoneId`). A time in the spring-forward gap rejects the entry, the repeated autumn hour is read as standard time, and missing time zone data throws `TimeZoneNotFoundException` instead of guessing. `ObservationCandidate.ObservedAt` is a `DateTimeOffset`.
  - `InputSchemaReader.Read(Stream)` leaves the caller's stream open; `CurrentSchemaVersion` is a property, so a host compiled earlier sees the value of the package it runs with.
  - `ObservationCandidate.EntryIndex` maps a candidate back to its entry in the file.
- Orchestration (`ExportOrchestrator`, `IObservationPublisher`, `PublishResult`):
  - `ExportOrchestrator` is the only way to publish: `IObservationPublisher.PublishAsync` is internal, so every candidate passes the value and evidence checks, and the interface is implemented only by this package's adapters.
  - `PublishOptions.Commit` defaults to false: the dry run goes through the same steps as a commit run (login, taxon, duplicate check) and stops before the first write. `PublishResult.Description` carries the German text that would become public. Entries of the same file that a commit run would skip as duplicates of each other all say `WouldCreate` in a dry run.
  - `PublishStatus`, `PublishStep` and `INaturalistLoginFailure` have explicit, stable values; `PublishStatus` is grouped (0-9 written, 10-19 dry run, 20-29 skipped, 30-39 not finished). The iNaturalist-shaped parts of the result (`PublishStep`, `WouldResume` / `Resumed`, the attached flags) are documented as provisional until a second platform exists.
  - `RunAsync(InputDocument, ...)` returns a `RunReport` (rejected entries, warnings, results, `IsComplete`, `CountByStatus`, `WarningsFor`), so a host shows one object before the commit run.
  - The platform-neutral value checks run on every candidate, so one built in code is judged like one read from a file (`SkippedInvalidEntry`). Such a candidate is also rejected for an empty name, a non-finite coordinate, an unknown `TimeZoneId` or an offset that does not match it, and its name is normalized like the reader's.
  - Evidence is read once per candidate, checked (not empty, PNG / WAV signature) and uploaded as the checked bytes (`SkippedMissingEvidence`, `SkippedInvalidEvidence`).
  - A failure that would repeat for every candidate stops the run after that candidate's `Failed` result, like a cancellation (`IsComplete` false): for iNaturalist, any failure to obtain a token (login denied or timed out, no port, a token store that cannot save, a network error in the token exchange). A browser login is therefore not reopened for every candidate.
  - Cancellation does not throw: `RunAsync` returns the results so far, and a `Cancelled` result carries the observation id, the attached flags and the interrupted stage (`PublishResult.InterruptedStep`, also set on `Failed`). An `OperationCanceledException` that is not the caller's (an HTTP timeout) is a `Failed` result.
- iNaturalist adapter, see `docs/inaturalist-setup.md` and `docs/inaturalist.md`:
  - OAuth login (Authorization Code + PKCE) through a loopback listener, which falls back to up to three OS-assigned ports when the configured one is in use, ignores stray requests, and ends with `INaturalistLoginException` (`Reason`: `ListenerUnavailable`, `TimedOut`, `Denied`) when no token is obtained. The OAuth token is exchanged for the API JWT and renewed silently.
  - Token storage: `INaturalistTokenStore` with `CanSave` (the login is refused before the browser opens when the store cannot save), and `ProtectedFileTokenStore` (DPAPI on Windows; elsewhere only with the plaintext opt-in, mode `0600`; atomic writes; an unreadable file counts as "no token").
  - An API request answered with 401 renews the API token silently from the stored login and is repeated once per candidate (safe for writes: the request was refused before processing).
  - The observation carries the local date and time (`observed_on_string`, `yyyy-MM-dd HH:mm:ss`) and no zone: with coordinates iNaturalist takes the zone from them, so `TimeZone` must be the zone of the recording place.
  - Strict taxon resolution, live for every candidate: an exact match of an active taxon with the expected rank (two words: species, one word: genus) that is Chiroptera or lies below it (a homonym outside the bats never matches); synonyms, ambiguous names, wrong ranks and names of three or more words are skipped with the reason (`SkippedUnresolvedTaxon`). BatInspector's group and uncertain values are filed under a broader taxon (`Nyctaloid`, `Social` and `?` under Chiroptera, `Mbart` under *Myotis*), keeping the original value as the species guess. `PublishResult.TaxonName` names the taxon used.
  - Validation of iNaturalist's limits before the login, also in a dry run (`INaturalistValidator`): dates more than 130 years back, a latitude of exactly ±90, the species name length, and evidence over `INaturalistOptions.MaxEvidenceBytes` (default 20 MB). iNaturalist's own error messages are passed through unchanged.
  - Options that would switch off a safety check are refused when the publisher or authenticator is created (`ArgumentException`): `DuplicateCheckRadiusKm` not finite or not above 0, `MaxEvidenceBytes` outside 1 to 20,000,000, `MinRequestInterval` under one second (pacing cannot be switched off), a `RedirectUri` that is not on this machine (127.0.0.1, localhost, [::1]), an `AuthorizationTimeout` of zero or less. The base URLs are not options (the client secret and tokens go to them).
  - Narrow public API: `INaturalistAuthenticator.LoginAsync` returns the user name, not the tokens; `EnsureAuthenticatedAsync` and `EvidenceFile` / `EvidenceFiles` are internal; `INaturalistToken.ToString()` shows only the user and the expiry.
  - `INaturalistOptions.TagList` over iNaturalist's limits (750 characters minus room for the resume tag, 255 per tag) makes the `INaturalistPublisher` constructor throw, instead of rejecting every entry.
  - Observation creation with the spectrogram as photo and the recording as sound, and a German description built from the entry.
  - Duplicate check against the user's own observations (same taxon, day and place: `SkippedDuplicate` with the existing id). A re-run completes an observation that an earlier run created but could not finish (`WouldResume`, `Resumed`), recognized by a `batinspector:<hash>` tag every observation gets (a hash of species, instant and coordinates), so the description can change; nothing is ever deleted.
  - The user profile (`GET /v1/users/me`) is asked once per API token for both the login name and the user id of the duplicate check.
  - Request pacing and opt-in retries: `MinRequestInterval` (default one second), `MaxAttempts` (default 1 = no retry), `RetryBaseDelay` and `MaxRetryDelay`. Only repeats that cannot create anything twice are made: any request after a 429, reads also after a 5xx, a network error or a timeout, writes only after a failed connection setup. `Retry-After` is honored. `INaturalistApiException` carries the status, `RetryAfter`, the full `ResponseBody` and a `Message` with at most 1000 characters of it.
- Every `await` in the library uses `ConfigureAwait(false)`, so no continuation returns to the host's UI thread and a host that blocks on a result from that thread cannot deadlock.
- Logging through `ILogger` (optional): source-generated messages with stable event IDs and names, no token at any level, a created observation's id at Information right after creation, a `Failed` candidate at Error with its exception. See `docs/logging.md`.
- Documentation in English and German: README, setup guide, input file reference, iNaturalist mapping (`docs/inaturalist.md`), the requests sent to iNaturalist (`docs/inaturalist-api.md`) and the logging contract.
